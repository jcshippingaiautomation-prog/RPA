# ชุดทดสอบถอยหลัง (golden set)

กัน "แก้บรีฟหรือ Master ของลูกค้ารายหนึ่ง แล้วของรายอื่นพังโดยไม่มีใครรู้"
เคสจริงที่เคยเกิด: แก้บรีฟสยามฮิตาชิ → พิกัดศุลกากรหายทั้งใบทุกรายการ
และ: ตั้งช่องใน Master เป็น "ไม่กรอก" → ชื่อลูกค้า/เลขอินวอยซ์หายทั้งชุด

## รัน
```
npm run build && npm run golden          # replay — เร็ว ฟรี ผลคงที่
npm run build && npm run golden -- live  # เรียก AI จริง (เสียเงิน) จับบรีฟที่เปลี่ยน
GOLDEN_ONLY=qcine-us npm run golden      # เฉพาะชุดเดียว
```
ไม่เขียนฐานข้อมูล ไม่แตะ DCTK — ใช้ `prepareDeclarationRecord()` ซึ่งเป็น
ขั้นตอนเดียวกับตอนอัปโหลดจริง แค่หยุดก่อนบันทึก

## เฉลยมาจากไหน
`expectHeader` / `expectItems` ถอดมาจาก **ใบขนที่เจ้าหน้าที่ยื่นกรมฯ จริง**
ไม่ใช่จากที่ระบบเราคำนวณเอง — ไม่งั้นจะเป็นการทดสอบว่า "ระบบยังทำผิดเหมือนเดิมไหม"

| ชุด | เฉลยจาก |
|---|---|
| qcine-us | DCTK000035927 (IN03462 → อเมริกา) |
| hitachi-kw | DCTK000035738 (KW000985 → คูเวต · ขาย SG ส่ง KW) |

## เพิ่มชุดใหม่
1. อัปโหลดเอกสารด้วย `AI_DEBUG=/tmp/ai.json` เพื่อเก็บคำตอบดิบของ AI
2. ตรวจว่าใบที่ได้ตรงกับใบขนจริงทุกช่อง (`pull-master-cli` ช่วยอ่านใบจริงมาเทียบ)
3. สร้าง `golden/<ชื่อ>.json` ใส่ `aiAnswer` (ข้อความดิบ) + `expectHeader` + `expectItems`
4. `sources` ใส่ path ใน Supabase storage ไว้สำหรับโหมด live
