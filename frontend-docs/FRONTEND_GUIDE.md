# คู่มือ Frontend — ระบบ RPA Import DCTK (DCTK Automation)

เอกสารนี้อธิบาย **ทุกหน้า/ทุก element ของ frontend** เพื่อใช้ (1) เป็นคู่มือการใช้งาน และ (2) ส่งให้ทีมออกแบบ (Claude design) ปรับปรุง UI/UX

> ภาพประกอบทั้งหมดอยู่ในโฟลเดอร์ `screenshots/` (อ้างอิงในแต่ละหัวข้อ)

---

## ภาพรวมระบบ

ระบบช่วยงานชิปปิ้ง (customs broker) สร้าง **ใบขนสินค้าขาออก** ในระบบกรมศุลกากร (DCTK) แบบอัตโนมัติ:

```
อัปโหลดเอกสาร/ดึงอีเมล → AI สกัดข้อมูล → ตรวจ/แก้ → กด "รัน" → RPA กรอกเข้า DCTK → ได้ PDF ใบขน
```

**ผู้ใช้ 2 ระดับ:** `admin` (เข้าถึงทุกอย่าง รวมหน้าตั้งค่า) / `user` (ใช้งานทั่วไป ไม่เห็นหน้าตั้งค่า)

**โครงหน้าจอ:** Sidebar ซ้าย (โลโก้ + เมนู + ผู้ใช้/ออกจากระบบ) + เนื้อหาหลักขวา (หัวข้อ + เครื่องมือ + ตาราง)

**ภาษา:** ไทยทั้งหมด · ฟอนต์ Noto Sans Thai · โทนสีน้ำเงินเข้ม + ขาว

## 2. หน้า "รายการใบขน" (หน้าหลัก)

📷 `screenshots/02-list.png`

หน้าทำงานหลัก แสดงใบขนทั้งหมด หัวข้อ "รายการใบขน" + คำโปรย "จัดการใบขนสินค้าทั้งหมดในที่เดียว"

### 2.1 การ์ดสถิติ (บนสุด — 3 ใบ)
- **ทั้งหมด** (`#cTotal`, ไอคอน list, ฟ้า) — จำนวนใบขนทั้งหมด
- **พร้อมรัน** (`#cReady`, ไอคอน inbox, เหลือง) — รอกดรัน
- **เสร็จแล้ว** (`#cDone`, ไอคอน check, เขียว) — สร้างใน DCTK แล้ว

### 2.2 แถบเครื่องมือ (Toolbar)
ซ้าย: ตัวกรอง **ลูกค้า** (`#filterCustomer`) · **สถานะ** (`#filterStatus`)
ขวา: ปุ่ม **ดึงอีเมลตอนนี้** (`#btnPollEmail`) · **อัปโหลดไฟล์** (`#btnUpload`) · **สร้างรายการ** (`#btnCreate`) · refresh (`#btnRefresh`)

### 2.3 ตาราง (9 คอลัมน์)
| คอลัมน์ | ข้อมูล |
|---------|--------|
| ☑ | checkbox เลือกแถว (header `#checkAll` เลือกทั้งหมด) |
| ลูกค้า | customer_name |
| Consignee | ผู้รับสินค้า |
| Invoice | เลขที่ใบกำกับ |
| ETD | วันส่งออก |
| มูลค่า | ราคา + สกุลเงิน |
| ที่มา | badge: อีเมล / อัปโหลด / สร้างเอง |
| สถานะ | badge (ดูตารางสถานะด้านล่าง) |
| จัดการ | ปุ่ม: รายละเอียด · 📋 copy · 🗑 ลบ · ▶ รัน · ดูไฟล์ |

**ปุ่มในคอลัมน์จัดการ** (เรียงซ้าย→ขวา):
- **รายละเอียด** (`.actDetail`) — เปิด modal ดู/แก้
- **copy** (`.actCopy`) — สร้างสำเนา
- **ลบ** (`.actDelete`) — ลบรายการ
- **รัน** (`.actRun`, ปุ่มเข้ม) — สั่ง RPA กรอก DCTK (disabled ถ้ากำลังรัน)
- **ดูไฟล์** (`.actFiles`) — เปิด modal ดู PDF/ภาพ (จางถ้ายังไม่มีไฟล์)

### 2.4 แถบ Bulk (โผล่เมื่อติ๊กเลือกหลายแถว)
`#bulkBar` — นับจำนวน + ปุ่ม **รันที่เลือก** · **ลบที่เลือก** · **ยกเลิกเลือก**

### 2.5 สถานะ (Status badge)
| สถานะ | สี | ความหมาย |
|-------|-----|---------|
| พร้อมรัน | ฟ้า | ข้อมูลพร้อม กดรันได้ |
| รอคิว | เหลือง | ส่งเข้าคิวแล้ว |
| กำลังรัน | เหลือง | RPA กำลังทำงาน |
| เสร็จ · สร้างแล้ว | เขียว | สร้างใบใน DCTK + มี PDF |
| แก้แล้ว | ส้ม | แก้ใบเดิมแล้ว |
| ผิดพลาด | แดง | **คลิกได้** → เปิด modal ดูสาเหตุ |

### 2.6 อัปเดตสด (Real-time)
ใช้ SSE (`/api/events`) — สถานะ/รายการอัปเดตเองโดยไม่ต้อง refresh (เห็น log RPA ไหลสดตอนรัน)

## 6. Modal: รายละเอียด / แก้ไข

📷 `screenshots/06-modal-detail.png`

เปิดจากปุ่ม **รายละเอียด** (หรือคลิก badge สถานะ "ผิดพลาด") — modal ใหญ่สุด มีหลายส่วน:

1. **สถานะ** (บนสุด) — badge + ข้อความสถานะ
2. **กล่องตรวจข้อมูล** — ถ้าข้อมูลไม่ครบ แสดง error/warning ที่ต้องแก้ก่อนรัน (ปุ่มรันจะ disabled)
3. **กล่องสาเหตุผิดพลาด** — ถ้า RPA fail แสดง "ติดที่..." + ปุ่ม "ดู log เต็ม"
4. **ฟอร์มข้อมูล** (`.md-edit`) — 25 ช่องหลัก แก้ไขได้
5. **ตารางรายการสินค้า** (`.it-edit`) — multi-item 14 คอลัมน์ (รหัสสินค้า/น้ำหนัก/ราคา/พิกัด/FOC) + เพิ่ม/ลบแถว
6. **เอกสารแนบ** (`#mdDocs`) — ไฟล์ที่เกี่ยวข้อง

**ปุ่มล่าง:** ลบรายการ · **บันทึก** (`#mdSave`) · **แก้ไขและรัน RPA** (`#mdEdit`, ส้ม — แก้ใบเดิมใน DCTK) · **รัน RPA สร้าง** (`#mdRun`, เขียว — สร้างใบใหม่)

## 8. หน้า "ตั้งค่า" (เฉพาะ admin) — 4 แท็บ

เมนู **ตั้งค่า** (ซ่อนสำหรับ user ทั่วไป) มี 4 แท็บ:

### 8.1 แท็บ "อีเมล"
📷 `screenshots/08-settings-email.png`

- **ดึงอีเมลอัตโนมัติ** (ล็อกไว้) — สวิตช์เปิด/ปิด + ความถี่ (ปิดใช้งานชั่วคราว)
- **Allowlist** — รายชื่ออีเมลผู้ส่งที่อนุญาต (เพิ่ม/ลบ/โหลดใหม่) ระบบประมวลผลเฉพาะอีเมลจากผู้ส่งในรายการ

### 8.2 แท็บ "AI & RPA"
📷 `screenshots/09-settings-airpa.png`

- **AI Model** (`#modelSel`) — เลือกโมเดล Gemini ที่ใช้สกัด (flash/pro/lite/พิมพ์เอง)
- **ตั้งค่า RPA (DCTK)** — URL/Username/Password ของ DCTK, slow_mo, timeout, headless, ส่งอีเมลหลังเสร็จ

### 8.3 แท็บ "ลูกค้า"
📷 `screenshots/10-settings-customer.png`

ส่วนสำคัญ — ตั้งกฎการสกัด/กรอกต่อลูกค้า:
- **AI ตั้งค่าลูกค้าใหม่** — ใส่ชื่อลูกค้า + subject ตัวอย่าง → AI วิเคราะห์อีเมลจริง → ร่าง "คู่มือการสกัด" ให้ตรวจ/แก้/บันทึก
- **Field Rules** — ต่อลูกค้า กำหนดแต่ละช่อง (จาก AI / กำหนดเอง / ไม่ใช้) + preset + extraction rules + ขอภาพหน้าจอ
  - จัดกลุ่ม 3 หน้า: หัวใบขน / ใบกำกับ(Invoice) / รายละเอียดสินค้า

### 8.4 แท็บ "ผู้ใช้"
📷 `screenshots/11-settings-users.png`

- **สร้างผู้ใช้** — อีเมล + รหัสผ่าน + สิทธิ์(user/admin) → ระบบยืนยันอีเมลอัตโนมัติ
- **ตารางผู้ใช้** — อีเมล · สิทธิ์(badge) · สถานะ · สร้างเมื่อ · ลบ

## ภาคผนวก: 25 ช่องข้อมูลใบขน (DCTK)

จัดกลุ่มตาม 3 หน้าในระบบ DCTK:

**หน้า 1 — หัวใบขน:** customer_name(ลูกค้า), consignee_name(ผู้รับ), buyer_country_code(ประเทศผู้ซื้อ), destination_country_code(ปลายทาง), vessel_name(เรือ), voyage_number(เที่ยว), release_port_code(ท่าตรวจปล่อย), loading_port_code(ท่ารับบรรทุก), tax_payment_method_code(วิธีชำระภาษี), etd

**หน้า 2 — ใบกำกับ/Invoice:** invoice_number, invoice_date, incoterms, currency(สกุลเงิน), total_goods_amount(มูลค่า), freight_charge(ค่าระวาง), insurance_charge(ค่าประกัน), shipping_mark

**หน้า 3 — รายละเอียดสินค้า:** description_eng(ชื่อสินค้า), net_weight_kg, gross_weight_kg, net_weight_ton, container_or_volume_qty(จำนวน/ปริมาณ), container_unit_code(หน่วย)

> รายการสินค้า (multi-item) แต่ละรายการมีเพิ่ม: รหัสสินค้า, ยี่ห้อ, พิกัดศุลกากร, หน่วยปริมาณในใบขน, FOC(ของแถม), ค่าประกันต่อรายการ

## หมายเหตุสำหรับทีมออกแบบ (Claude design)

- **เป้าหมาย UX:** ลดขั้นตอน upload→สกัด→ตรวจ→รัน ให้ลื่นไหล · เห็นสถานะ/ความคืบหน้าชัด
- **จุดที่ใช้บ่อยสุด:** หน้ารายการ (ตาราง + ปุ่มรัน + ดูไฟล์) และ modal รายละเอียด (แก้ข้อมูล + รายการสินค้า)
- **ผู้ใช้จริง:** พนักงานชิปปิ้ง — ต้องการความเร็ว + เห็นข้อผิดพลาดชัดเพื่อแก้ก่อนรัน
- **ข้อจำกัดปัจจุบัน:** ตาราง modal รายการสินค้า 14 คอลัมน์กว้างมาก (scroll แนวนอน) — เป็นจุดที่ออกแบบใหม่ได้
- **โทนสีเดิม:** น้ำเงินเข้ม (#1f2a44) + ขาว — ปรับได้ตามดีไซน์ใหม่
